AI Basics & Real-world Applications

Unit 1 · Healthcare · Finance · E-commerce · Transportation

What is Artificial Intelligence (simple definition)

AI is the field of making computers do tasks that normally require human intelligence — recognising patterns, making decisions, understanding language, and improving with experience.

Machine Learning is the part of AI where the system learns patterns from data instead of being given fixed rules.

Deep Learning is a subset of ML that uses multi-layer neural networks (you will meet them in Modules 4–5).

3Blue1Brown — “But what is a neural network?” Classic visual introduction (watch even if you already know the basics).

1. Healthcare

  • Medical imaging — CNNs detect tumours, fractures, pneumonia from X-rays and CT scans (often better than average radiologists on narrow tasks).
  • Drug discovery — models predict which molecules are likely to bind to a target protein, cutting years of lab work.
  • Clinical decision support — systems flag high-risk patients or suggest possible diagnoses from electronic health records.
  • Personalised treatment — recommend dosage or therapy based on patient history and genetics.
Real example Google’s DeepMind and many research groups have published models that detect diabetic retinopathy from retinal photos — a leading cause of blindness that is treatable if caught early.

2. Finance

  • Fraud detection — supervised and unsupervised models score every transaction in milliseconds.
  • Credit scoring — models combine traditional features with alternative data to decide loan approvals.
  • Algorithmic trading — models forecast short-term price moves or optimise portfolios.
  • Customer service chatbots — NLP models answer routine queries and route complex ones.

3. E-commerce & Retail

  • Recommendation systems — collaborative filtering + content-based models (the “people who bought X also bought Y”).
  • Search ranking — learning-to-rank models decide which products appear first.
  • Demand forecasting — time-series and gradient-boosted models predict inventory needs.
  • Visual search — upload a photo and find similar products (computer vision embeddings + similarity search).

4. Transportation

  • Autonomous vehicles — perception (detect cars, pedestrians, lanes), prediction, and planning.
  • Route optimisation — reduce fuel and delivery time (classic operations research + ML).
  • Traffic prediction — forecast congestion using historical + real-time sensor data.
  • Predictive maintenance — sensors + models predict when a vehicle or aircraft part will fail.

The AI / Machine Learning Pipeline

Unit 2 · From raw data to a running system

Why a pipeline?

Building a model is not “run one script and done”. Real systems go through a repeatable sequence of steps so that results are reliable, reproducible, and maintainable.

Standard high-level pipeline

  1. Problem definition — What business question are we answering? What is success?
  2. Data collection — Gather historical data, labels, external sources.
  3. Data preparation — Clean, handle missing values, encode, scale, split train/validation/test.
  4. Feature engineering — Create useful signals from raw columns (you will do this deeply in Module 3).
  5. Model selection & training — Choose algorithms, tune hyperparameters, train.
  6. Evaluation — Metrics on held-out data (accuracy, precision, recall, RMSE, AUC…).
  7. Deployment — Serve the model via API, batch jobs, or edge devices.
  8. Monitoring & retraining — Detect drift, collect new labels, retrain when needed.

End-to-end ML pipeline — from data collection to monitoring

Training vs Inference

  • Training — heavy computation, uses labels, produces a model file (weights).
  • Inference (prediction) — lightweight, runs the saved model on new data, returns answers in real time or batch.

Most production cost is often in serving many inference requests, not in the one-time training job.

Tiny numerical mental model

Imagine predicting house price from size (sq ft).

  • Data: 5 houses with (size, price)
  • Model: simple linear regression → price ≈ w × size + b
  • Training: find w and b that minimise squared error (Module 1 gradient descent)
  • Inference: new house of 1200 sq ft → plug into the formula and get a price

Scale this idea to millions of rows and hundreds of features and you have a real pipeline.

AI Cloud Ecosystem

Unit 3 · Core ML Services + Development Tools (GCP focus)

Why cloud for AI/ML?

  • GPUs and TPUs are expensive to own; cloud lets you rent them by the hour
  • Managed storage, databases, and data pipelines scale automatically
  • ML services (AutoML, training, serving, monitoring) reduce boilerplate
  • Collaboration, versioning, and security are built-in

Core ML services (Google Cloud examples)

The NIAI curriculum emphasises Google Cloud. Key pieces:

  • Vertex AI — unified platform for training, deploying, and managing models
  • BigQuery / BigQuery ML — analytics warehouse + SQL-based ML
  • Cloud Storage — object storage for datasets and model artefacts
  • Dataflow — batch and stream data processing (Apache Beam)
  • Cloud Composer — managed Apache Airflow for pipeline orchestration
  • TPUs & GPUs — accelerators for deep learning training

Development tools you will use

  • Notebooks — Vertex AI Workbench / Colab / Jupyter for exploration
  • SDK & CLI — gcloud, Vertex AI Python SDK
  • Experiment tracking — Vertex Experiments, or open-source (MLflow, Weights & Biases)
  • Containers — Docker images for reproducible training and serving
  • CI/CD — Cloud Build + deployment pipelines (Module 8 MLOps)

Typical first cloud workflow (mental picture)

  1. Upload a CSV to Cloud Storage
  2. Create a Vertex AI dataset pointing to that file
  3. Launch a training job (custom container or AutoML)
  4. Register the resulting model
  5. Deploy an endpoint
  6. Send prediction requests via REST or the Python client

You will practice pieces of this in later modules and in the Capstone.

Cost awareness Always set budget alerts. Stop idle notebooks and undeploy unused endpoints. Free tiers and credits exist for students — use them carefully.

Module 2 — Key takeaways

  • AI is already embedded in healthcare, finance, retail and transport.
  • A proper pipeline covers problem → data → features → train → evaluate → deploy → monitor.
  • Cloud (especially Vertex AI + BigQuery + Dataflow) removes the need to manage servers and GPUs yourself.
  • Training produces a model; inference uses that model to answer new questions.
